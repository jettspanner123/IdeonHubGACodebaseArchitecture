# Use Spring Security + JJWT instead of mirroring SignForge's hand-rolled auth

The Global Authenticator service was scaffolded to mirror SignForge's Spring Boot configuration (same Spring Boot/Java versions, same starter set) for consistency across WePLM services. SignForge itself hand-rolls both password hashing (single-round salted SHA-256, no key-stretching) and JWTs (manual HMAC-SHA256 signing with a hardcoded secret literal in source, and non-constant-time signature comparison) with no `spring-boot-starter-security` dependency. We deliberately did not carry these two practices into the Authenticator: we added `spring-boot-starter-security` (for `BCryptPasswordEncoder` and the security filter chain) and the JJWT library (`io.jsonwebtoken:jjwt-api/impl/jackson`) instead. This is the one service in the stack whose entire responsibility is authentication, so its JWT handling and password hashing carry more weight than they do in SignForge's usage — the exact-mirror-of-SignForge policy applies to versions and project structure, not to this pair of security primitives.
